# 两个最值得上手的前沿方向实战指北

> 面向有 Python / OpenCV / PyTorch 基础的大专机器视觉同学。两个方向都做到“当天能跑起来、一周能出demo、毕设能收尾”。

---

## 方向 A：3D Gaussian Splatting（3DGS）与神经渲染

### 是什么

用手机绕物体/房间拍一圈视频或几十张照片，重建出一个**可以实时漫游、新视角自由观看**的 3D 场景。它的核心是把场景表示成几十万~几百万个带位置、颜色、透明度和协方差（椭球形状）的 3D 高斯点，光栅化渲染速度可达 30~100+ FPS。

**与 NeRF 的区别**（面试高频）：
| | NeRF | 3DGS |
|---|---|---|
| 表示 | 隐式 MLP 场 | 显式高斯点云 |
| 渲染 | 逐像素体渲染，慢 | 光栅化，实时 |
| 训练 | 数小时~数天 | 几分钟~1 小时 |
| 编辑 | 难 | 直观（点可增删、可分割） |

### 为什么值得学

- 2023 SIGGRAPH 起爆火，2024-2026 工业界落地爆发：数字孪生、AR/VR 商品展示、机器人场景理解、SLAM 重建。
- 门槛低：一张 RTX 3060/4060 就能训练中等规模场景；手机端已有实时 demo（如 Luma、Polycam）。
- 视觉工程师的天然延伸：从“2D 检测分割”跨到“3D 理解”，简历辨识度高。

### 环境

- GPU：训练建议 ≥8GB 显存（3060 起），渲染无所谓。
- 工具推荐二选一：
  - **nerfstudio**：一站式框架，`ns-train` / `ns-viewer` 极友好，适合入门。
  - **graphdeco-inria/gaussian-splatting**（官方仓库）+ **gsplat**（更快的后端）：性能更强。

```bash
# 1) 建环境（conda 24.x + CUDA 12.1 较稳）
conda create -n 3dgs python=3.10 -y
conda activate 3dgs

# 2) 装 nerfstudio（含 COLMAP 依赖，会自动下载）
pip install nerfstudio

# 3) 用手机拍一段视频，抽帧并做位姿估计
ffmpeg -i room.mp4 -vf fps=2 frames/%04d.jpg   # 2fps抽帧，避免太多冗余
ns-process-data images --data frames/ --output-dir data/room   # 内部调COLMAP

# 4) 训练 3DGS
ns-train splatfacto --data data/room         # nerfstudio里3DGS的实现叫splatfacto
# 训练完按终端提示启动浏览器 viewer
ns-viewer --load-config outputs/room/splatfacto/*/config.yml
```

### 最小可跑示例思路

1. 拍一段 30~60 秒绕物体/房间的视频（**慢、稳、光均匀、别太反光**）。
2. `ns-process-data` 抽帧 + COLMAP 求相机位姿（常见要 5~15 分钟）。
3. `ns-train splatfacto` 训练 10~30 分钟，`ns-viewer` 在浏览器里拖鼠标漫游。
4. 导出 `point_cloud.ply`，用 [antimatter15/splat](https://github.com/antimatter15/splat) 这类 WebGL viewer 手机打开看。

### 常见坑

- **COLMAP 位姿估计失败**：纹理太少（白墙）、运动模糊、反光/透明物体 → 补纹理、重拍。
- **显存爆**：分辨率调低（`--downscale-factor 2`）、控制点数上限。
- **训练后“糊成一团”**：常是抽帧太密或太稀；保持视角覆盖均匀，别只朝一个方向走。
- **⚠ 商用许可**：官方 3DGS 是 **非商用** 许可，商业落地请查 gsplat / 部分开源实现许可。
- 手机端实时渲染目前以 WebGL viewer 为主，原生 App 需移植，注意别高估。

### 数据集

- **Mip-NeRF 360 / Tanks & Temples / LLFF**：经典评测集，练流程。
- **Objaverse / GSO**：物体级单物体重建。
- **自采**：最重要——手机拍自己的工位、货架、机械零件，就是毕设素材。

### 毕设选题

- “基于 3DGS 的车间货架数字孪生与远程巡检原型”
- “单物体 3DGS 重建 + Web 端商品 3D 展示页面”
- “3DGS 与 YOLO 联动的 3D 场景目标标注可视化”

## 方向 B：视觉语言模型（VLM）微调与应用

### 是什么

让大模型“看图说话”。以 **Qwen2.5-VL / InternVL2.5 / LLaVA-1.6** 为代表，输入图片+文本，输出问答、描述、结构化结果。开源 7B 级模型在 8~16GB 显存卡上可 LoRA 微调，也能用 Ollama 本地一键跑。

### 为什么值得学

- 传统 CV 只给“类别+框”，VLM 能直接输出**自然语言报告**：如“第 3 号螺栓表面有 2mm 划痕，判定为不合格”。
- 工业界需求明确：缺陷描述、质检报告生成、文档/图纸理解、产线异常解释。
- 与大模型浪潮同频，就业方向宽。

### 环境

- **推理**：Ollama（最低门槛）或 transformers + vLLM。
- **微调**：LLaMA-Factory（强烈推荐，官方支持 Qwen2.5-VL / InternVL 的 LoRA 训练）。

```bash
# 1) 本地推理（最低门槛，一张 8~12GB 卡即可）
ollama pull qwen2.5vl:7b
ollama run qwen2.5vl:7b "这张工业图片中有什么缺陷？用一句话回答。" --image defect.jpg

# 2) LoRA 微调（LLaMA-Factory 版）
git clone https://github.com/hiyouga/LLaMA-Factory && cd LLaMA-Factory
pip install -e ".[torch,metrics]"

# 数据准备：JSON 格式（图像路径 + 多轮对话），示例标注重在"缺陷-位置-等级"
# 训练命令（示意）
llamafactory-cli train \
  --model_name_or_path Qwen/Qwen2.5-VL-3B-Instruct \
  --stage sft --do_train \
  --dataset your_defect_sft --template qwen2_vl \
  --finetuning_type lora --lora_target all \
  --output_dir out/qwen_vl_defect \
  --per_device_train_batch_size 1 --gradient_accumulation_steps 8 \
  --learning_rate 1e-4 --num_train_epochs 2 --bf16 true
```

### 最小可跑示例思路

1. **先零样本**：Ollama 跑 Qwen2.5-VL，拿自己拍的缺陷图问“有没有划痕/凹坑/漏装”，看效果。
2. 若整体效果差 → **LoRA 微调**：准备 300~1000 条样本（图片 + “缺陷类型 / 位置 / 描述 / 结论” 四段式标注）。
3. 用 LLaMA-Factory 训 1~2 epoch，导出合并权重。
4. 写一个 Flask/Gradio 小服务：`上传图片 → VLM 输出结构化 JSON → 前端表格展示`。

### 常见坑

- **显存**：7B 全参微调要 80G 级，务必 **LoRA + bf16 + batch=1 + grad accumulation**。
- **幻觉**：VLM 爱“编”不存在的细节。工业场景必须用**带定位信息（如“左上角”）的标注 + 结构化输出约束**（JSON schema）来压。
- **数据配比**：至少 30% 正常样本（“无缺陷”），否则模型看啥都报缺陷。
- **不要用它替代专用检测模型**：VLM 慢（秒级），适合“报告生成/复核/复杂长尾”，前端检测仍走 YOLO。
- 图像分辨率、比例要与训练一致，否则描述错位。

### 数据集

- **通用**：COCO Captions、TextVQA、DocVQA、ChartQA。
- **工业**：MVTec AD（图像+类别 → 让 VLM 生成描述）、NEU-DET 钢材缺陷、自采产线图。
- 构建一套自采“图+四段式标注”数据，本身就是毕设加分项。

### 毕设选题

- “基于 Qwen2.5-VL 微调的钢材表面缺陷自然语言报告生成系统”
- “产线接线端子漏装/错装的 VLM 复核 + YOLO 前端联动方案”
- “Ollama 本地部署的工业图纸问答助手”
- “VLM 对 MVTec AD 的零样本 vs LoRA 微调对比实验与评测报告”

## 学习路线建议（4 周）

| 周 | 3DGS 方向 | VLM 方向 |
|---|---|---|
| 1 | 装 nerfstudio，流程跑通一个 Mip360 场景 | Ollama 部署 Qwen2.5-VL，跑通 50 张图问答 |
| 2 | 自拍场景训练 + viewer 展示 | 标注 200 条数据，LoRA 微调跑起来 |
| 3 | 3DGS+YOLO 可视化小联动 | Gradio 前端 + JSON 结构化输出服务 |
| 4 | 封装成毕设 demo / 视频 | 做对比实验与评测 |

两个方向的共同点：**先跑通端到端，再做数据/评测**。任何一端卡住，先切另一条线的“最小闭环”，避免陷在环境里出不来。
